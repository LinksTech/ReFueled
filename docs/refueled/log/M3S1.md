## Befund zum Testpfad
`bbgpu_init` braucht keine Gast-Speicher/Runtime; die `runtime_*`-Symbole werden als Stubs
(wie tests/test_gpu_runtime_stubs.cpp, dort aber sigjmp_buf) im Testprogramm definiert. `bbgpu_init`
öffnet das SDL3-Fenster (eigener Thread `bb:window`), legt über `GnmDriver::RegisterLib` den
`Vulkan::Presenter` an (Instance, Gerät, Surface, Swapchain, Frames) und über `VideoOut::RegisterLib`
den `VideoOutDriver`. Dessen Present-Thread zeichnet von selbst Leerbilder, solange kein Port offen ist
(`DrawBlankFrame` = `PrepareBlankFrame(true)` + `Present`). Ein eigener Aufruf von Prepare/Present aus dem
Testprogramm kollidiert mit diesem Thread (Validierung: "command pool used simultaneously",
"vkBeginCommandBuffer not called", Absturz in nvoglv64.dll) - der Test wartet daher nur und zählt.
Das Testbild ist deshalb das Leerbild des Präsentierers (schwarz); eine andere Löschfarbe/ein Verlauf
bräuchte eine Änderung in `PrepareBlankFrame` (shadps4), die nicht vorgenommen wurde.
Nach `presenter.reset()` im Testprogramm stürzt der Prozess ab (Driver-Thread nutzt den Präsentierer
weiter): kein Fehler der Bibliothek, der Test zerstört ihn deshalb nicht. Das Schließen läuft wie im
Spiel: `SDL_EVENT_QUIT` -> Fenster-Thread -> `std::_Exit(0)`.

## Befehle

```
bash build-windows.sh                                  # sacredfire.exe, libbbgpu.a, libpf.a (ok)
cmake -S gpu -B out/win/gpu ; env -u VULKAN_SDK ninja -C out/win/gpu m3-present
```

## Abnahme
- (a) Fenster: erfüllt, SDL-Treiber `windows`, 1280x720.
- (b) Instanz/Gerät/Surface/Swapchain über den Code der GPU-Bibliothek: erfüllt (RTX 5080, Swapchain B8G8R8A8Unorm, 3 Bilder).
- (c) Testbild einige Sekunden präsentiert: erfüllt mit Einschränkung - schwarzes Leerbild, ca. 295 Bilder in 5 s (60 Hz).
- (d) Fenster schließt ohne Absturz, Exit 0: erfüllt (SDL_EVENT_QUIT -> `_Exit(0)`).
- (e) Validierung: erfüllt, 0 Fehler mit Kern- und Sync-Validierung (SDK 1.4.350.0).

## Weitere Befunde
- Die Schicht des SDK 1.3.296.0 (steht zuerst in VULKAN_SDK/PATH) ist älter als der Treiber (Vulkan 1.4.351):
  sie meldet nur "pNext chain includes unknown VkStructureType 1000574000/1000567000" bei vkCreateDevice.
  Mit der Schicht 1.4.350.0 (VK_LAYER_PATH) entfällt das.
- `Failed to open ... cache\TEST00000\profile.bin` (Error-Zeile): erster Start ohne Pipeline-Cache, harmlos.
- `build-windows.sh` und die Test-Programme brauchen `-lpthread -lkernel32 -lmincore` (wie der Exe-Link).

## Offen
- Visuell unterscheidbares Testbild (Farbe/Verlauf) nicht umgesetzt (Änderung an PrepareBlankFrame nötig).
- Die Pipeline-Cache-Pfade unter Windows (user_dir) sind hier nur über BB_GPU_USER_DIR geprüft.

## Review Opus
Nur WIN32, EXCLUDE_FROM_ALL, keine Bibliotheksquelle geändert. `#define private public` im Test ist ein bewusster Testbehelf (nur Swapchain-Format und Tick lesen), kein Muster für Produktcode. Befund 1 (Presenter vom VideoOut-Thread benutzt) ist für M3 wichtig: eigenes Testbild nur über den Driver-Thread, nicht parallel.
