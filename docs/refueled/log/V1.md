## Nicht geändert (Begründung)
- `mprotect`/`sysconf`: in dieser Datei kein direkter Aufruf. Seitenschutz geht über `Core::AddressSpace::Protect`
  (`impl.Protect`, Z. ~682; `address_space.Protect`, uffd-Teil) – das ist ein Shim (`gpu/shim/core/address_space.h`),
  nicht V1. Dort muss `pf_vm_protect` stehen, damit der Windows-Weg (D13) funktioniert.
- userfaultfd (`UffdImpl`, uffd-Includes, `BB_UFFD`-Auswertung im Konstruktor, `getenv`, `std::jthread`, `std::runtime_error`):
  vollständig innerhalb `#ifdef __linux__` (Z. ~457 bis `#endif // __linux__`; Konstruktor-Zweig Z. ~632). Unter `_WIN32` bleibt nur `SignalImpl`
  (Seitenschutz-Weg); keine uffd-Typen außerhalb der Klammer. `BB_UFFD` wird unter Windows nicht gelesen.
- `#ifndef _WIN64 <sys/mman.h>, adaptive_mutex.h / #else <windows.h>`: Upstream-Zeilen mit eigenem Windows-Zweig, bleiben.
  `<sys/mman.h>` bleibt unter `!_WIN64`; auf Windows ist `LockType = Common::SpinLock` (`spin_lock.h` im `#else` von `__linux__`).
