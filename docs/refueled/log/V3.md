## Entscheidungen
1. `src/runtime.h` ist aus C++ nicht einbindbar (keine `extern "C"`-/`__cplusplus`-Klammern, C-Konstrukte);
   darum bleibt die lokale `extern "C"`-Deklaration, mit PfMemHandle-Signatur, wortgleich zur
   Deklaration in runtime.h:108. (Alternative für Opus: `extern "C" {}` um den Include.)
2. Plattformunterscheidung nur im Shim: neue `BbGuestMemory::PlatformSupported()` (Linux true;
   Windows false + einmalige Zeile `bbport: guest-in-place GPU memory is not supported on Windows`).
   `PcModelGpu()`/`Usable()` liefern dann false; `Install()` kehrt nach den Env-Prüfungen zurück
   (Log nur, wenn der Nutzer das Modell verlangt hat). Der Rückfall in `buffer_cache.cpp:485-490`
   (`DisableGuestInPlace`) greift damit.
3. `vk_instance.cpp:377`: unter Windows fehlen die Erweiterungen `VK_KHR_external_memory_fd`/
   `..._dma_buf`, `add_extension` liefert false, `IsGuestMemoryExportSupported()` ist false. Keine
   Änderung nötig (D14).
4. `buffer.cpp:114`: der Arena-Konstruktor kann vor dem Rückfall in `BufferCache` laufen
   (Initialisierungsliste); darum zusätzlich `&& BbGuestMemory::PlatformSupported()`, sonst würde
   unter Windows ein Buffer mit `eDmaBufEXT` angelegt. Zweiter Konstruktor (Z.146) nur mit Chunks
   erreichbar, die es unter Windows nie gibt: unverändert.
5. `munmap` der Probe-Mappings → `pf_vm_free` (= `munmap`, pf_memory_linux.c:78). Fehlerwert von
   `pf_handle_map` ist NULL (nicht MAP_FAILED), Vergleiche entsprechend umgestellt.
