# Paket-Log K7 – pf_exception Windows (Opus)

- `pf_exception_win32.c`: erster VEH (AddVectoredExceptionHandler(1)), Zuordnung
  ACCESS_VIOLATION/IN_PAGE_ERROR/ILLEGAL/PRIV/BREAKPOINT/SINGLE_STEP → PfFaultKind, Zugriffsart aus
  ExceptionInformation[0] (0/1/8), zuerst `pf_win32_memory_transient_fault` (K1), dann Handler in
  Registrierungsreihenfolge; Breakpoint: RIP+1 vor den Handlern (Linux-Konvention), bei "nicht
  behandelt" zurück. Andere Ausnahmen (C++, Debug-Ausgabe, Stack-Überlauf) → CONTINUE_SEARCH.
  PfContext = CONTEXT* (pf_win32_internal.h), Register über offsetof-Tabelle, EFlags 32 Bit.
  `pf_fault_resume_at`: lädt pf_jmp_buf in den CONTEXT (Layout PF_JMP_* in pf_win32_internal.h,
  K6 schreibt pf_jmp_win32.S danach), rax = value. `pf_exit_now` = TerminateProcess.
  Watchdog: ein Timer-Thread mit SRW-Lock + Condition Variable, jedes pf_watchdog_start setzt neu,
  0 schaltet ab; Callback bekommt context NULL (wie im Header).
- `pf_base_win32.c`: pf_init registriert den VEH vor pf_tls_init; timeBeginPeriod(1) über
  LoadLibrary("winmm.dll") (keine Import-Lib nötig).
- `test_exception.c` (gemeinsam mit K8): Windows-Hilfen (VirtualAlloc/VirtualProtect, erzeugter
  Code für int3 und TF), Kontext-Roundtrip, unbehandelt + Watchdog als Kindprozess (das eigene
  Programm mit Rollenargument, SetErrorMode ohne Absturzdialog).
- `test_stubs.c`: pf_exception-Stub-Prüfungen entfernt.

das pf_setjmp_impl aus K6 braucht). Linux unverändert: alle 8 Plattformtests grün (exception 32).
