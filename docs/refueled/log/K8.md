## Aufbau
- Kontext: `pf_context_get/set` über `uc_mcontext.gregs[REG_*]` (Tabelle für alle 18 PfReg,
  EFLAGS = REG_EFL), `struct PfContext { ucontext_t *native; }` aus pf_linux_internal.h.
- `pf_fault_add_handler`: bis 16 Einträge in statischem Array; der Eintrag wird vollständig
  geschrieben, danach der Zähler mit release veröffentlicht (der Dispatcher liest mit acquire);
  Hinzufügen unter Mutex. `sigaction` je Signal einmal bei der ersten Registrierung einer Art;
  die vorherige Aktion wird je Signal gemerkt. Fehler: kinds 0 / unbekannte Bits / handler NULL
  -> PF_EINVAL, voll -> PF_ENOSPC, sigaction scheitert -> PF_EIO.
- Dispatcher: kind aus Signal (SIGTRAP: `si_code == TRAP_TRACE` -> SINGLE_STEP, sonst BREAKPOINT),
  address = si_addr, access = UNKNOWN, host_code = Signal; Handler in Registrierungsreihenfolge,
  deren Maske passt; erster HANDLED beendet. Keiner: vorherige Aktion (SA_SIGINFO-Form oder alte
  Form, SIG_DFL/SIG_IGN/NULL ausgenommen), sonst `signal(sig, SIG_DFL); raise(sig)`. Das ist die
  Kette aus den Shims, Zeichen für Zeichen.
- `pf_fault_resume_at`: Signal aus thread-lokaler Variable (im Dispatcher gesetzt) mit
  `pthread_sigmask(SIG_UNBLOCK)` entsperren, dann `pf_siglongjmp`.
- `pf_watchdog_start`: Callback + user atomar ablegen, `sigaction(SIGALRM)`, `alarm(seconds)`;
  0 -> `alarm(0)`. Der Callback bekommt den PfContext des unterbrochenen Threads. Anders als
  probe.c ruft der Handler danach NICHT selbst `_exit(128+sig)`; das tut der Callback (Opus: der
  Watchdog-Callback in probe.c muss `_exit(128 + SIGALRM)` selbst aufrufen). Kehrt der Callback
  zurück, läuft der Thread weiter.
- `pf_log_linux.c`: `write(2, ...)`-Schleife, EINTR wird wiederholt, andere Fehler beenden still.
