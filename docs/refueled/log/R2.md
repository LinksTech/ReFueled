## Korrektur (Opus-Prüfung): Abbruch beim ersten Fehler
Der alte Callback `remove_entry` in runtime_savedata.c gibt `remove(path)` zurück, nftw bricht also
beim ersten Fehler ab. Die erste Fassung lief weiter; das war eine Verhaltensänderung.
- `pf_fs_linux.c`: Callback gibt `remove(path)` zurück (genau wie vorher) und merkt errno
  (`_Thread_local`); nftw-Rückgabe != 0 -> PF_E* aus gemerktem errno, sonst aus errno von nftw.
- `pf_fs_win32.c`: `remove_walk` kehrt sofort zurück, sobald ein Fehler vorliegt; die Schleife
  über FindNextFileW endet, das Verzeichnis wird nach einem Fehler in den Kindern nicht mehr
  versucht zu löschen.
- `test_fs.c`: kein Test setzte das Weiterlaufen voraus. Neu, nur Windows: `test_locked` (offene
  Datei ohne FILE_SHARE_DELETE) -> `pf_fs_remove_tree == PF_EBUSY`, Datei bleibt, nach fclose -> 0.
  Linux-Gegenstück weggelassen: Rechte auf /mnt/c sind nicht verlässlich, /tmp ist nicht erlaubt.
- Header pf_fs.h unverändert (kommt beim Merge).
