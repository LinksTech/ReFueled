# Paket-Log IF-11 (Opus): Low-Heap-Grenze und errno-Zelle nur unter Windows

Verhaltensabweichung Linux: keine (Rückbau von D21 Nr. 1 und 2 auf den Stand vor dem Port)

Ausgeführt von Opus, geprüft von Opus. Auftrag Projektleitung 2026-10-13.

## Warum nur Windows
Unter Linux liegen die gast-sichtbaren Host-Objekte schon unter 1 TiB (D10): `-no-pie`-Exe, brk-Heap
mit mallopt, und glibc legt die statische TLS eines Threads (also `_Thread_local guest_errno`) oben
in dessen Stack, der für Gast-Threads aus `runtime_low_map` kommt. Unter Windows liegen C-Heap,
`_Thread_local`-Daten der Exe und Host-Stacks dagegen oberhalb von 1 TiB.

## alt ↔ neu (Linux)
| vor dem Port | nach K2/K5 | jetzt (IF-11) |
|---|---|---|
| runtime_memory.c `while (low_next+size<=USER_MIN)` | `<= LOW_MAP_END` = USER_MIN − 512 MiB | `LOW_MAP_END` = USER_MIN − `PF_LOW_HEAP_SIZE` (0) = USER_MIN, gleich |
| – | `pf_low_heap_init(LOW_MAP_END, 512 MiB)` | `pf_low_heap_init(USER_MIN, 0)`; Linux-Fassung tut nichts, gleich |
| runtime_thread.c `static _Thread_local int32_t guest_errno; … return &guest_errno;` | Zelle im TCB-Block / Low-Heap-Zelle | `PF_GUEST_ERRNO_IN_TCB` 0: `return &guest_errno`, gleich |
| `total=offset+256` | `offset+256+16` | `offset+256+0`, gleich (gleiche aligned_alloc-Größe und memset-Länge) |

## Windows
Werte unverändert (512 MiB, Zelle im TCB-Block); die Zweige laufen mit Konstanten 1 bzw. 512 MiB
wie bisher. Prüfung: MSVC `/W4 /WX` mit `_Static_assert` auf PF_LOW_HEAP_SIZE, PF_GUEST_ERRNO_IN_TCB
und LOW_MAP_END = 0xFE0000000. Diff: 3 Dateien, 27 Zeilen hinzu, 8 geändert.
