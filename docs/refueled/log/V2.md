## vk_breadcrumbs.cpp
Keine Aenderung: Es gibt keine POSIX-Aufrufe, `process_vm_readv` steht nur in einem Kommentar (Z. 97). `<sys/stat.h>`/`<unistd.h>` (Z. 11-12) werden nicht benutzt (kein stat/getpid/mkdir im Code) und existieren in MinGW; beim ersten Windows-Build pruefen, sonst die beiden Includes streichen.

## Offene Punkte / Schnittstellenbedarf (fuer Opus)
1. `pf_thread_cpu_time_ns` liest nur die CPU-Zeit des *aufrufenden* Threads. Die Statistik liest aber vom Stats-Thread (driver.cpp) die Uhr des GPU-Threads ueber die in `bbport_toggles.h` abgelegte `clockid_t` (`gpu_thread_clock`). Umstellen aendert das Linux-Verhalten (Wert nur noch beim Schreiben des GPU-Threads frisch), also nicht umgestellt: Linux-Code unveraendert, unter Windows bleibt `gpu_ns` 0 ("GPU thread on CPU 0 ms"). Vorschlag, falls gewuenscht: neue Funktion `pf_thread_cpu_clock_handle()`/`pf_thread_cpu_time_of(handle)` in pf_thread.h, dann sind beide Seiten plattformneutral.
2. `pf_gpu_memory_in_use` liefert nur die Summe VRAM+GTT; die Statistikzeile zeigt beide getrennt. Deshalb Linux-Schleife behalten. Vorschlag: Signatur um `uint64_t *vram, uint64_t *gtt` erweitern (oder zweite Funktion), dann kann die Schleife entfallen. Unter Windows liefert die Funktion derzeit PF_ENOSYS (Anzeige 0).
3. `getrusage` (Fehlerzaehler/Kontextwechsel, RUSAGE_THREAD und RUSAGE_SELF) hat kein pf-Aequivalent; nur Linux (Statistikzeilen unter Windows 0). Bedarf an einer pf-Funktion nur, wenn diese Zahlen unter Windows gebraucht werden.
4. `x86intrin.h` (vk_draw_pipe.h) und `__builtin_return_address` bleiben (clang).
5. `runtime_fault_recover` (bbport_toggles.h:15) ist noch `sigjmp_buf*`; Paket S2 stellt auf `pf_sigjmp_buf*` um. Ohne S2 passt `&recover` unter Windows nicht.
